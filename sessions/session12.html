جلسه ۱۲: مدیریت داده‌های نامتوازن و پرت (Imbalanced Data & Outliers)

اهداف یادگیری

در پایان این جلسه، دانشجو باید بتواند:

  • مسئله داده نامتوازن را تشخیص دهد و پیامدهای آن را بشناسد
  • چهار راهکار اصلی (Undersampling, Oversampling, Class Weight, Threshold) را اجرا کند
  • الگوریتم SMOTE و خانواده آن را با جزئیات درک کند
  • روش‌های تشخیص Outlier (Z-Score, IQR, Isolation Forest, LOF, DBSCAN) را اعمال کند
  • تصمیم بگیرد که پرت‌ها را حذف، تبدیل یا نگه دارد
  • معیارهای ارزیابی مناسب مسائل نامتوازن (F1, AUC-ROC, Precision-Recall) را انتخاب کند
  • از ابزارهای imbalanced-learn و PyOD استفاده کند

پیش‌نیازهای جلسه

  • آشنایی با دسته‌بندی (جلسه ۹)
  • دانش پایه از KNN (K نزدیک‌ترین همسایه)
  • درک معیارهای ارزیابی
داده نامتوازن (Imbalanced Data): مجموعه داده‌ای که در آن توزیع کلاس‌ها یکنواخت نیست — یک یا چند کلاس به‌مراتب کمتر از سایرین نمونه دارند.

۱۲.۱.۱ تعریف دقیق

اگر کلاس اکثریت Nmajority نمونه و کلاس اقلیت Nminority نمونه داشته باشد:

Imbalance Ratio = Nmajority / Nminority
Imbalance Ratio طبقه‌بندی مثال
۱:۱ تا ۴:۱ متعادل تا نسبتاً نامتوازن تشخیص گربه/سگ
۵:۱ تا ۲۰:۱ نامتوازن متوسط تشخیص بیماری شایع
۱۰۰:۱ تا ۱۰۰۰:۱ نامتوازن شدید تشخیص تقلب، عیب تولید
> ۱۰۰۰:۱ نامتوازن بسیار شدید (Severely) تشخیص رویداد نادر، ناهنجاری

۱۲.۱.۲ کاربردهای واقعی

اکثر مسائل جذاب یادگیری ماشین، ذاتاً نامتوازن هستند:

  • تشخیص تقلب بانکی: از هر ۱۰٬۰۰۰ تراکنش، فقط ۵ تا تقلبی
  • تشخیص بیماری نادر: از هر ۱۰۰٬۰۰۰ نفر، ۱ نفر مبتلا
  • تشخیص نقص در تولید: از هر ۱ میلیون قطعه، ۱۰۰ تا معیوب
  • پیش‌بینی ریزش مشتری: از ۱۰۰۰ مشتری، ۵۰ ریزش می‌کنند
  • تشخیص هرزنامه: ۷۰٪ ایمیل‌ها در Gmail اسپم هستند
  • تشخیص تومور بدخیم: از ۱۰۰ بیمار مشکوک، ۵ مبتلا
  • تشخیص کلاهبرداری بیمه: بسیار نادر ولی پرهزینه

۱۲.۱.۳ مشکل اصلی چیست؟

پارادوکس Accuracy: اگر ۹۹٪ تراکنش‌ها سالم هستند، مدلی که همیشه «سالم» بگوید، ۹۹٪ دقت خواهد داشت — ولی هیچ تقلبی را شناسایی نمی‌کند! یعنی مدل بی‌ارزش است ولی Accuracy بالا نشان می‌دهد.

۱۲.۱.۴ چرا مدل‌ها Bias به کلاس اکثریت دارند؟

  • بسیاری از الگوریتم‌ها تابع هزینه را در سطح کلی کمینه می‌کنند
  • اگر ۹۹٪ نمونه‌ها کلاس A هستند، پیش‌بینی همه به A بهترین نتیجه را می‌دهد
  • مدل یاد نمی‌گیرد چگونه کلاس B را تشخیص دهد چون نمونه کافی ندیده
  • حتی با تنظیمات، مدل به B بی‌توجه می‌ماند
Resampling: تغییر توزیع کلاس‌ها با افزایش یا کاهش نمونه‌ها — تا قبل از آموزش مدل، داده‌ها متعادل‌تر شوند.

۱۲.۲.۱ Undersampling (کاهش کلاس اکثریت)

الف) Random Undersampling

به‌صورت تصادفی نمونه‌های کلاس اکثریت حذف می‌شوند تا تعدادشان با اقلیت برابر شود.

مزایا: ساده، سریع، حجم داده کم می‌شود

معایب: از دست رفتن اطلاعات بالقوه

ب) NearMiss

نمونه‌های اکثریتی که به نمونه‌های اقلیت نزدیک‌تر هستند، نگه داشته می‌شوند (بقیه حذف).

سه نسخه: NearMiss-1 (کمترین فاصله متوسط)، NearMiss-2 (کمترین فاصله دورترین)، NearMiss-3 (بیشترین فاصله نزدیک‌ترین).

ج) Tomek Links

جفت‌هایی از دو کلاس مختلف که نزدیک‌ترین همسایه یکدیگرند → نمونه اکثریت حذف می‌شود. مرز بین کلاس‌ها تمیزتر می‌شود.

د) Edited Nearest Neighbors (ENN)

نمونه‌ای که با اکثریت همسایه‌هایش هم‌کلاس نیست → حذف.

۱۲.۲.۲ Oversampling (افزایش کلاس اقلیت)

الف) Random Oversampling

نمونه‌های اقلیت به‌صورت تصادفی کپی می‌شوند تا تعدادشان با اکثریت برابر شود.

مزایا: ساده، بدون از دست دادن اطلاعات

معایب: Overfitting شدید (مدل نمونه‌های تکراری را حفظ می‌کند)

ب) SMOTE (Synthetic Minority Over-sampling Technique)

ایده اصلی: به جای کپی کردن، نمونه‌های جدید «مصنوعی» بین نمونه‌های واقعی اقلیت تولید کن. این کار هم تعداد را افزایش می‌دهد و هم تنوع ایجاد می‌کند.

پ) ADASYN (Adaptive Synthetic Sampling)

نسخه تطبیقی SMOTE — نمونه‌های مصنوعی بیشتر در مناطق «دشوار» (نزدیک مرز) تولید می‌کند. مدل در یادگیری مرز بهتر عمل می‌کند.

۱۲.۲.۳ ترکیب Undersampling و Oversampling

  • SMOTE + Tomek: ابتدا افزایش، سپس حذف نمونه‌های مرزی
  • SMOTE + ENN: ابتدا افزایش، سپس حذف نویزی

۱۲.۲.۴ جدول مقایسه راهکارها

روش مزایا معایب زمان استفاده
Random Undersampling سریع، ساده از دست دادن اطلاعات داده بسیار زیاد
NearMiss حفظ نمونه‌های مهم پیچیده‌تر مرز اهمیت دارد
Random Oversampling ساده Overfitting شدید فقط حجم داده مهم است
SMOTE تنوع، کاهش Overfitting ممکن است نمونه‌های عجیب تولید کند پیش‌فرض و محبوب
ADASYN تمرکز بر مناطق دشوار ممکن است Overfit شدید در مرز مسائل با مرز پیچیده

قاعده تجربی:

اگر تعداد نمونه‌های اقلیت > ۱۰۰۰: معمولاً SMOTE کافی است.

اگر تعداد نمونه‌های اقلیت ۱۰۰-۱۰۰۰: ترکیب SMOTE + Tomek بهتر است.

اگر تعداد نمونه‌های اقلیت < ۱۰۰: علاوه بر SMOTE، از Class Weight هم استفاده کنید.

۱۲.۳.۱ ایده اصلی

SMOTE در فضای ویژگی (Feature Space)، بین دو نمونه اقلیت، یک نمونه مصنوعی قرار می‌دهد:

۱۲.۳.۲ الگوریتم گام‌به‌گام

  1. یک نمونه تصادفی x از کلاس اقلیت انتخاب کن
  2. K نزدیک‌ترین همسایه x (که همگی اقلیت هستند) را پیدا کن
  3. از بین K همسایه، یکی را تصادفی انتخاب کن (xnn)
  4. نمونه مصنوعی بین x و xnn تولید کن

۱۲.۳.۳ فرمول ریاضی

xnew = x + λ × (xnn − x)
         که λ ∈ [0, 1] تصادفی

اگر λ = 0 → همان x، اگر λ = 1 → همان xnn، اگر λ = 0.5 → وسط.

۱۲.۳.۴ مثال بصری

دو نمونه اقلیت داریم: (۲، ۳) و (۴، ۵).

اگر λ = 0.3 باشد:

xnew = (۲، ۳) + 0.3 × ((۴، ۵) − (۲، ۳)) = (۲، ۳) + 0.3 × (۲، ۲) = (۲٫۶، ۳٫۶)

نقطه جدید: (۲٫۶، ۳٫۶) — بین دو نقطه اصلی ولی نه کپی.

۱۲.۳.۵ انواع SMOTE

الف) Borderline-SMOTE

فقط روی نمونه‌های اقلیتی که در مرز با کلاس اکثریت هستند کار می‌کند. فرض: این نمونه‌ها اطلاعات بیشتری دارند.

ب) SMOTE-NC (Numerical + Categorical)

نسخه‌ای برای داده‌هایی که هم عددی و هم طبقه‌ای دارند. برای ستون‌های طبقه‌ای، از Mode (پرتکرارترین مقدار) استفاده می‌کند.

ج) SMOTE-N (Categorical Only)

وقتی همه ویژگی‌ها طبقه‌ای هستند. روش خاص برای ساخت نمونه.

۱۲.۳.۶ هشدارهای مهم

هشدار ۱: SMOTE فقط روی ویژگی‌های عددی کار می‌کند. ویژگی‌های طبقه‌ای باید به‌صورت جداگانه Encode شوند.

هشدار ۲: SMOTE نمونه‌های «واقعی» تولید نمی‌کند، بلکه نمونه‌های «مصنوعی» در فضای ویژگی می‌سازد. این می‌تواند در بعضی مسائل منجر به نمونه‌های عجیب شود.

هشدار ۳: SMOTE قبل از Train/Val/Test split اعمال شود (وگرنه Data Leakage رخ می‌دهد).

هشدار ۴: اگر نمونه‌های اقلیت بسیار کم باشد (مثلاً ۵ نمونه)، SMOTE نمی‌تواند همسایه پیدا کند.

۱۲.۳.۷ پیاده‌سازی

# در Python با کتابخانه imbalanced-learn
from imblearn.over_sampling import SMOTE, ADASYN
from imblearn.under_sampling import RandomUnderSampler, TomekLinks

# ساده

X_resampled, y_resampled = smote.fit_resample(X_train, y_train)

# ترکیبی

X_resampled, y_resampled = smt.fit_resample(X_train, y_train)

# به همراه مدل در Pipeline
pipeline = ImbPipeline([

])
Class Weight: در تابع هزینه، به اشتباهات روی کلاس اقلیت جریمه بیشتر بده. این کار مدل را به سمت یادگیری بهتر کلاس اقلیت سوق می‌دهد — بدون تغییر داده‌ها.

۱۲.۴.۱ تابع هزینه با وزن

تابع هزینه استاندارد:

J = Σ L(yi, ŷi)

تابع هزینه با وزن‌دهی:

J = Σ wi × L(yi, ŷi)

اگر برای کلاس اقلیت w = 50 و اکثریت w = 1، مدل باید برای تشخیص اقلیت خیلی بیشتر تلاش کند.

۱۲.۴.۲ محاسبه خودکار وزن

در scikit-learn، پارامتر class_weight='balanced' وزن‌ها را خودکار محاسبه می‌کند:

wj = N / (K × Nj)

که N تعداد کل، K تعداد کلاس‌ها، Nj تعداد نمونه‌های کلاس j.

مثال: ۱٬۰۰۰ نمونه، ۲ کلاس

  • کلاس ۰: ۹۹۰ نمونه → w = ۱۰۰۰ / (۲ × ۹۹۰) ≈ ۰٫۵
  • کلاس ۱: ۱۰ نمونه → w = ۱۰۰۰ / (۲ × ۱۰) = ۵۰

هر اشتباه روی کلاس اقلیت، ۱۰۰ برابر جریمه دارد!

۱۲.۴.۳ پیاده‌سازی

# Logistic Regression با وزن خودکار

# وزن دستی
weights = {0: 1, 1: 100}
model = LogisticRegression(class_weight=weights)

# در Random Forest
from sklearn.ensemble import RandomForestClassifier

# در XGBoost
import xgboost as xgb
model = xgb.XGBClassifier(scale_pos_weight=ratio)

۱۲.۴.۴ مزایا و معایب

مزایا معایب
داده‌ها بدون تغییر (مناسب برای حجم زیاد) ممکن است Overfit در اقلیت شود
ساده، یک پارامتر وزن‌دهی بیش‌ازحد → Recall بالا ولی Precision پایین
قابل ترکیب با سایر تکنیک‌ها نیاز به تنظیم دقیق وزن
بدون از دست دادن اطلاعات فقط در بعضی الگوریتم‌ها قابل‌تنظیم است
در XGBoost خیلی مؤثر
Threshold Tuning: به جای default threshold = 0.5، آستانه‌ای انتخاب کنید که بین Precision و Recall تعادل ایجاد کند. این روش، مدل را تغییر نمی‌دهد، فقط تصمیم‌گیری را.

۱۲.۵.۱ مفهوم

بیشتر مدل‌های دسته‌بندی، احتمال P(y=1) می‌دهند. پیش‌فرض: اگر P > 0.5 → کلاس ۱. ولی این آستانه در مسائل نامتوازن خوب نیست.

مثال: مدلی که احتمال تقلب را پیش‌بینی می‌کند:

  • P = 0.3 → پیش‌فرض: «عادی»
  • P = 0.3 → با threshold = 0.2: «مشکوک»

با کاهش threshold، Recall بالا می‌رود (بیشتر تقلب‌ها شناسایی می‌شوند) ولی ممکن است Precision کاهش یابد.

۱۲.۵.۲ روش‌های انتخاب Threshold

الف) Youden's J Statistic

Threshold که J = Recall + Specificity − ۱ را بیشینه می‌کند.

ب) F1-Optimal Threshold

Threshold که F1-Score را بیشینه می‌کند.

ج) Cost-Sensitive Threshold

با توجه به هزینه‌های FN و FP در کسب‌وکار، threshold بهینه محاسبه می‌شود.

Threshold_optimal = argmaxt [Cost_FN × FN(t) + Cost_FP × FP(t)]

۱۲.۵.۳ نمودار Precision-Recall

برای مسائل نامتوازن، این نمودار مفیدتر از ROC است:

  • محور X: Recall
  • محور Y: Precision
  • هدف: بیشینه کردن هر دو

Average Precision (AP): مساحت زیر منحنی P-R. بالاتر = بهتر.

در مسائل نامتوازن، Accuracy کاملاً گمراه‌کننده است. از معیارهایی استفاده کنید که عملکرد روی کلاس اقلیت را مستقل اندازه می‌گیرند.

۱۲.۶.۱ چرا Accuracy بد است؟

در مسئله‌ای با ۹۹٪ کلاس اکثریت:

  • مدل همیشه «اکثریت» → Accuracy = ۹۹٪
  • ولی هیچ نمونه اقلیتی شناسایی نمی‌شود → Recall کلاس اقلیت = ۰
  • F1 کلاس اقلیت = ۰

۱۲.۶.۲ معیارهای توصیه‌شده

الف) F1-Score (میانگین هارمونیک)

F1 = 2 × (Precision × Recall) / (Precision + Recall)

اگر Recall یا Precision صفر باشد، F1 = ۰. مدلی که هیچ اقلیتی شناسایی نکند، F1 = ۰ می‌گیرد.

ب) Balanced Accuracy

Balanced Accuracy = (Recallmajority + Recallminority) / 2

میانگین Recall هر کلاس. اگر مدل فقط اکثریت را پیش‌بینی کند، این مقدار ≈ ۵۰٪ است.

ج) Matthews Correlation Coefficient (MCC)

MCC = (TP×TN − FP×FN) / √[(TP+FP)(TP+FN)(TN+FP)(TN+FN)]

ضریب همبستگی بین پیش‌بینی و واقعیت. بین −۱ و +۱. در مسائل نامتوازن، قابل‌اعتمادترین معیار.

د) Cohen's Kappa

مشابه MCC، توافق بین پیش‌بینی و واقعیت را اندازه می‌گیرد.

ه) AUC-PR (Average Precision)

مساحت زیر منحنی Precision-Recall. بهتر از AUC-ROC در نامتوازن شدید.

۱۲.۶.۴ جدول مقایسه

معیار مناسب نامتوازن؟ توضیح
Accuracy ✗ بسیار بد متحمیل کلاس اکثریت می‌شود
F1-Score ✓ خوب متعادل بین P و R
Balanced Accuracy ✓ خوب میانگین Recall هر کلاس
MCC ✓✓ عالی قابل‌اعتمادترین، بین -۱ تا +۱
AUC-ROC ✓ قابل‌قبول ممکن است در شدید، بیش‌بین باشد
AUC-PR ✓✓ عالی بهترین برای شدید
Outlier (داده پرت): نقطه‌ای که از الگوی کلی داده‌ها فاصله زیادی دارد. این نقاط می‌توانند خطا، نویز، یا رویدادهای واقعی نادر باشند.

۱۲.۷.۱ سه نوع Outlier

الف) Global Outliers (سراسری)

از کل توزیع دور است.

مثال: در داده‌های دمای تهران (میانگین ۲۰°C)، ثبت ۵۰°C قطعاً خطاست.

ب) Contextual Outliers (متنی)

در یک زمینه خاص عجیب است ولی در کل داده عادی.

دمای ۳۰°C در تهران در تابستان طبیعی، ولی در زمستان عجیب است.

مصرف ۱۰۰ کیلووات در ساعت ۳ بامداد طبیعی نیست (ولی در ساعت ۷ عصر طبیعی است).

ج) Collective Outliers (جمعی)

مجموعه‌ای از داده‌ها که با هم عجیب‌اند.

در یک ساعت خاص، ۱۰۰ تراکنش مشکوک از یک کارت صادر شده (نه یکی یکی، بلکه به‌صورت burst).

۱۲.۷.۲ علل ایجاد Outlier

  • خطای اندازه‌گیری: سنسور خراب، GPS دقیق نبودن
  • خطای ورود داده: عدد اشتباه تایپ شد
  • خطای پردازش: باگ در کد
  • پدیده واقعی نادر: اتفاق نادر ولی واقعی
  • توزیع ذاتاً Tail-Heavy: درآمد، ثروت

۱۲.۷.۳ روش‌های تشخیص

الف) Z-Score (آماری)

Z = (x − μ) / σ
آستانه |Z| سطح اطمینان کاربرد
> ۲ ۹۵٪ تشخیص ساده
> ۳ ۹۹٫۷٪ استاندارد صنعتی
> ۴ ۹۹٫۹۹٪ تشخیص بسیار سخت‌گیرانه

محدودیت: فقط برای توزیع نرمال (یا تقریبی). برای توزیع‌های نامتقارن مناسب نیست.

ب) IQR (روش چارکی)

IQR = Q3 − Q1
Lower Bound = Q1 − 1.5 × IQR
Upper Bound = Q3 + 1.5 × IQR

هر نقطه بیرون از بازه [Lower Bound, Upper Bound] پرت محسوب می‌شود.

مزیت: مناسب داده‌های غیرنرمال، مقاوم به خود پرت‌ها.

ج) Modified Z-Score (برای توزیع‌های نامتقارن)

M = 0.6745 × (x − median) / MAD

که MAD = Median Absolute Deviation. اگر |M| > ۳.۵ → پرت.

د) Isolation Forest (مبتنی بر ML)

ایده: Outlierها سریع‌تر از نقاط عادی جدا می‌شوند (با درخت‌های تصادفی).

نقطه عادی → عمق زیاد، نقطه پرت → عمق کم.

Anomaly Score بالا → پرت بودن.

ه) Local Outlier Factor (LOF)

ایده: Outlier نسبت به همسایگانش چگالی کمتری دارد.

مناسب داده‌هایی با چگالی‌های متفاوت در مناطق مختلف.

و) DBSCAN

نقاط Noise در DBSCAN = Outlier.

ز) One-Class SVM

یاد می‌گیرد مرز «عادی» را مشخص کند. هر چیز بیرون = outlier.

۱۲.۷.۴ جدول مقایسه

روش نوع مزیت محدودیت
Z-Score آماری ساده، تفسیرپذیر فقط نرمال
IQR آماری بدون فرض توزیع فقط تک‌بعدی
Isolation Forest ML چندبعدی، سریع ابرپارامتر contamination
LOF ML چگالی متغیر کند، حساس به K
DBSCAN ML خوشه‌بندی + تشخیص همزمان نیاز به ε و MinPts

۱۲.۸.۱ قانون طلایی

قبل از هر اقدامی: تحلیل کنید که Outlier خطاست یا واقعیت. گاهی Outlier ارزشمندترین نقطه داده است (مثلاً در تشخیص تقلب).

۱۲.۸.۲ روش‌ها

الف) حذف (Trimming)

ساده‌ترین روش. وقتی Outliner مطمئناً خطاست (مثلاً سن = ۲۰۰ یا دما = ۱۰۰۰°C).

خطر: ممکن است اطلاعات ارزشمندی از دست برود.

ب) Winsorization (کپسوله‌سازی)

به جای حذف، مقدار را به آستانه محدود کنید:

داده‌ها: [10, 12, 13, 14, 15, 200] (۲۰۰ پرت است)

Q3 = 14.75, Q1 + 1.5×IQR = 11.75

Winsorize: [10, 12, 13, 14, 15, 15.75] ← ۲۰۰ با ۱۵٫۷۵ جایگزین شد

ج) تبدیل ریاضی

  • Log Transform: x' = log(x + 1). دنباله بلند → کوتاه
  • Square Root: برای داده‌های شمارش
  • Box-Cox: تبدیل خودکار برای نرمال‌سازی
  • Yeo-Johnson: نسخه Box-Cox برای داده‌های منفی

    • د) جایگزینی (Imputation)

    با مقدار معقول جایگزین شود:

    • میانگین / میانه
    • مقدار همسایه (در سری زمانی)
    • پیش‌بینی با مدل (KNN، Random Forest)

    ه) نگه‌داری با مدل مقاوم

    از الگوریتم‌هایی استفاده کنید که نسبت به Outlier مقاوم‌اند:

    • Huber Loss (در رگرسیون، ترکیب MSE و MAE)
    • Random Forest (درخت‌ها robust هستند)
    • RANSAC (تکرار با حذف پرت)
    • Median Absolute Deviation (آماری)

    و) مدل‌سازی جداگانه

    Outlierها را به‌عنوان کلاس جداگانه در نظر بگیرید (یا طبقه‌بندی «پرت/عادی»).

    ۱۲.۸.۳ مثال: تشخیص تقلب بانکی

    داده: ۱۰٬۰۰۰ تراکنش، ویژگی «مبلغ»

    • ۹۹ تراکنش مبلغ کمتر از ۱ میلیون
    • ۱ تراکنش مبلغ ۵۰۰ میلیون! (آیا پرت؟)

    اگر با Z-Score آن را حذف کنیم، ممکن است بزرگ‌ترین تراکنش تقلبی را از دست داده باشیم!

    راه‌حل: Outlier را نگه داریم، ولی از Robust Scaler یا Log Transform استفاده کنیم تا تأثیر آن کم شود.

    ۱۲.۹.۱ تشخیص تقلب در بانک پاسارگاد

    مسئله: از ۱۰۰٬۰۰۰ تراکنش روزانه، فقط ۵۰ تا مشکوک.

    • Imbalance Ratio = ۲۰۰۰:۱
    • استفاده از SMOTE + Class Weight + Threshold Tuning
    • معیار ارزیابی: MCC و AUC-PR
    • مدل: XGBoost با scale_pos_weight

    ۱۲.۹.۲ تشخیص عیب در تولید (ایران‌خودرو)

    مسئله: از ۱ میلیون قطعه تولیدی، ۱۰۰۰ تا معیوب.

    • Imbalance Ratio = ۱۰۰۰:۱
    • ترکیب: SMOTE + Tomek Links
    • Isolation Forest برای تشخیص الگوهای عیب جدید

    ۱۲.۹.۳ تشخیص هرزنامه در پیام‌رسان‌های ایرانی

    مسئله: در ۱ میلیون پیام، ۳۰٪ اسپم هستند (نسبتاً متعادل‌تر).

    • TF-IDF + Logistic Regression با class_weight
    • Outlier: پیام‌هایی با ۱۰۰ لینک حذف

    ۱۲.۹.۴ تشخیص ریزش مشتری در اسنپ

    مسئله: از ۱۰۰٬۰۰۰ راننده، ۵۰۰۰ ریزش می‌کنند.

    • Imbalance Ratio = ۲۰:۱
    • SMOTE-ENN ترکیبی
    • معیار: F1-Score کلاس ریزش

    ۱۲.۹.۵ پیش‌بینی قیمت مسکن (Outlier)

    مسئله: در داده‌های دیوار، قیمت ۱ میلیارد تومان برای آپارتمان ۵۰ متری در منطقه ۳.

    • ممکن است اشتباه باشد → Winsorize
    • یا ممکن است واقعی و لوکس باشد → نگه‌داری
    مقدمه و معرفی مشکل (۸ دقیقه):

    با یک مثال شروع کنید: «فرض کنید می‌خواهیم مدلی بسازیم که تقلب در تراکنش‌های بانکی را تشخیص دهد. اگر از ۱۰۰۰ تراکنش، فقط ۱۰ تا تقلبی باشد، مدل می‌تواند همیشه بگوید تقلب نیست و ۹۹٪ دقت داشته باشد!». این مشکل داده نامتوازن است. تأکید کنید که دقت بالا همیشه خوب نیست — باید به کلاس اقلیت توجه کنیم.

    تکنیک‌های Resampling (۱۲ دقیقه):

    Undersampling را با کاهش کلاس اکثریت توضیح دهید: مثلاً از ۱۰۰۰ نمونه سالم، فقط ۱۰۰ تا نگه داریم. عیب: از دست دادن اطلاعات. Oversampling: از ۱۰ نمونه تقلبی، ۱۰۰ تا بسازیم. SMOTE: نقطه جدید بین نقاط اقلیت تولید می‌کند — نه دقیقاً کپی. این بهتر از کپی کردن است چون تنوع ایجاد می‌کند.

    نکته کلیدی: تأکید کنید که Resampling باید فقط روی Train Set انجام شود.

    SMOTE جزئیات (۸ دقیقه):

    SMOTE را با یک مثال گرافیکی توضیح دهید: دو نقطه اقلیت داریم، SMOTE یک نقطه جدید بین آنها قرار می‌دهد. این مثل Interpolation است. مزیت: داده جدید واقعی نیست ولی واقعی به نظر می‌رسد. Borderline-SMOTE فقط روی نقاط مرزی کار می‌کند که مهم‌ترند.

    Class Weight و Threshold (۶ دقیقه):

    Class Weight را با یک تشبیه توضیح دهید: «معلمی که به دانش‌آموز ضعیف‌تر بیشتر توجه می‌کند». در مدل، یعنی اشتباه روی کلاس اقلیت جریمه بیشتر دارد. Threshold Tuning ساده‌ترین راه است: آستانه ۰٫۵ را به ۰٫۳ کاهش دهید تا نمونه‌های مشکوک بیشتر شناسایی شوند.

    معیارهای ارزیابی (۶ دقیقه):
    مثال آموزشی: «اگر در تشخیص سرطان، مدلی بسازیم که همیشه «سرطان ندارد» بگوید، ۹۹٫۹٪ دقت خواهد داشت (چون سرطان نادر است) — ولی هیچ بیماری را شناسایی نمی‌کند!»

    F1 و MCC را معرفی کنید. بگویید: در مسائل نامتوازن، MCC قابل‌اعتمادترین است.

    داده‌های پرت (۸ دقیقه):

    پرت‌ها می‌توانند مهم باشند! مثال: در تشخیص تقلب، یک تراکنش خیلی بزرگ ممکن است تقلب باشد — نباید حذف شود. انواع: Global (از کل داده‌ها دور)، Contextual (در یک موقعیت خاص عجیب)، Collective (گروهی که با هم عجیب‌اند).

    تشخیص و مدیریت پرت (۸ دقیقه):

    Z-Score: اگر نقطه‌ای بیشتر از ۳ انحراف معیار از میانگین فاصله داشته باشد، پرت است. IQR: برای داده‌های غیرنرمال بهتر است — از چارک‌ها استفاده می‌کند. Winsorization: به جای حذف، مقدار را به آستانه محدود کنیم. تأکید کنید: قبل از حذف پرت، دلیلش را پیدا کنید!

    جمع‌بندی (۴ دقیقه):

    خلاصه: داده نامتوازن مشکل رایجی است — از SMOTE یا وزن‌دهی استفاده کنیم. داده‌های پرت را با دقت بررسی کنیم — گاهی اطلاعات مهمی دارند. همیشه معیارهای مناسب (F1, MCC, AUC-PR) را به جای Accuracy استفاده کنیم. تکلیف: دانشجویان باید یک دیتاست نامتوازن پیدا کنند و راه‌حل پیشنهاد دهند.

    فصل دوازدهم: مدیریت داده‌های نامتوازن و پرت

    ۱۲.۱ داده نامتوازن

    تعریف: Imbalance Ratio بالا. چالش: Accuracy گمراه‌کننده، Bias به سمت کلاس اکثریت، کلاس اقلیت مهم‌تر. مثال‌ها: تقلب، بیماری نادر، نقص تولید.

    ۱۲.۲ راهکارها

    Resampling:

    • Undersampling: Random, NearMiss, Tomek Links, ENN
    • Oversampling: Random (ضعیف), SMOTE (پیش‌فرض), ADASYN
    • ترکیب: SMOTETomek, SMOTEENN

    Class Weight: وزن بیشتر به اقلیت در تابع هزینه. ساده، یک‌خط کد.

    Threshold Tuning: آستانه بهینه به جای ۰٫۵ پیش‌فرض.

    معیارهای مناسب: F1, MCC, Balanced Accuracy, AUC-PR.

    ۱۲.۳ SMOTE

    ایده: نمونه مصنوعی بین دو نمونه اقلیت x_new = x + λ(x_nn - x). انواع: Borderline, SMOTE-NC, SMOTE-N. فقط عددی. فقط قبل از Split.

    ۱۲.۴ Outliers

    سه نوع: Global, Contextual, Collective. علل: خطا یا واقعیت نادر.

    ۱۲.۵ تشخیص Outlier

    Z-Score (|z|>3)، IQR (1.5×IQR)، Isolation Forest، LOF، DBSCAN، One-Class SVM.

    ۱۲.۶ مدیریت Outlier

    حذف (خطرناک)، Winsorization (جایگزینی با آستانه)، تبدیل (Log, Box-Cox)، جایگزینی (Imputation)، مدل مقاوم (Huber, Random Forest, RANSAC).

    خلاصه فصل:

    1. داده نامتوازن در مسائل واقعی بسیار رایج است
    2. SMOTE محبوب‌ترین تکنیک Oversampling
    3. Class Weight ساده‌ترین راه برای تنظیم مدل
    4. Accuracy در نامتوازن گمراه‌کننده — از F1, MCC, AUC-PR استفاده کنید
    5. Outlier می‌تواند خطا یا واقعیت ارزشمند باشد — قبل از اقدام، تحلیل کنید
    6. Isolation Forest و LOF قدرتمندترین روش‌های ML برای تشخیص Outlier

    تمرین‌های خودآزمایی:

    1. چرا Accuracy برای داده نامتوازن معیار مناسبی نیست؟ یک مثال عددی بزنید.
    2. تفاوت Oversampling و Undersampling چیست؟ کدام برای حجم داده زیاد مناسب‌تر است؟
    3. SMOTE چگونه نمونه جدید تولید می‌کند؟ فرمول آن را بنویسید.
    4. چرا Borderline-SMOTE از SMOTE معمولی بهتر است؟
    5. Class Weight چه زمانی بهتر از Resampling است؟
    6. یک مثال واقعی از Outlier بزنید و توضیح دهید چه تصمیمی باید گرفت.
    7. تفاوت Z-Score و IQR چیست؟ کدام برای داده با Outlier مناسب‌تر است؟
    8. MCC چه مزیتی نسبت به F1 دارد؟
